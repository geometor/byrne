geometor.byrne.pseudocode¶

Formal grammar, AST, and 3-way Rosetta metrics for Oliver Byrne’s 1847 Visual Pseudocode.

Models Oliver Byrne’s 1847 notation (Introduction, pp. ix–xi, xxvii–xxix) as a pointer-free, typed geometric value-token language:

  • Classical Euclidean Text (Heath / Heiberg): Pass-by-reference. Geometric objects are unnamed in ink; vertices carry alphabetic memory addresses (A, B, C, …) and prose dereferences composite tuples (line AB, angle BAC, triangle FBC, square ABFG) at every step.

  • Byrne 1847 Visual Pseudocode: Pass-by-value. Every geometric primitive is assigned a perceptual signature (kind, color, stroke, fill) that appears literally inside vertical symbolic equations (∴, ∵, =, +, ⊏, ⊐, ∥, ⊥, ∷) with marginal axiom/proposition citations.

  • GEOMETOR Formal Pseudocode (elements / model): Typed Constructive DAG. Explicit constructor steps (line, circle, intersect) and symbolic algebraic invariants over exact number fields.

geometor.byrne.pseudocode.analyze_visual_registers(program: ByrneProgram) → RegisterDiagnostic¶

Audit visual register allocation and collision freedom in program.

Distinguishes:

  1. Stroke modulation (dashed / dotted / solid-dotted) when 4 colors alone cannot separate adjacent collinear or overlapping elements;

  2. Composite tokens (yellow+black split angles or red/blue/black triangles);

  3. Intentional congruence twins (e.g. equal legs / A B / and / A C / in I.5 deliberately sharing red solid to encode AB = AC visually); and

  4. Ambiguous collisions (two unequal geom_ref entities sharing an identical register signature without a congruence_group declaration).
